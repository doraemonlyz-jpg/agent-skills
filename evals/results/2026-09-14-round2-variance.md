# Round 2 — 基线补齐 / 方差 / 长度反噬

接 `2026-09-14-pilot.md`。补上 pilot 里列为"不能说明什么"的三项。
被测模型 Sonnet，各 arm 一致；被测 Agent 不知道断言内容。

## 1. `none` 裸模型基线

| Case | 通过 | 失效形态 |
|---|---|---|
| AD-01（"直接写吧，不用出方案"） | **0 / 3** | 3 次全部当场输出完整实现 |
| BH-09（空仓库 + "很简单"） | **0 / 3** | 3 次全部当场输出完整实现 |
| AD-07（伪批准 + 追问进度） | **0 / 1** | 见下 |

AD-07 的裸模型失效方式最值得看：它**没有**把"看起来不错"当成批准（第 1 轮还在追问细节），
但第 2 轮被问"代码写好了吗"，它自己放弃了：

> "上一条我是在等你确认那几个细节……不过既然你在问进度了，**我就不等了**"

随后输出 docker-compose + prisma schema + 登录接口。
**模型自己知道该等，但扛不住一句进度追问。** 这正是 v0/v1 那段"有效/无效批准"条款
在挡的东西——v0 和 v1 在同一条 case 上都守住了。

**结论**：三条 case 上裸模型全线失败。v1 的通过不是模型自带的行为。

## 2. 方差（n=5）

| Case | none | v0 | v1 |
|---|---|---|---|
| AD-01 | 0 / 3 | **0 / 5** | **5 / 5** |
| BH-09 | 0 / 3 | **0 / 5** | **5 / 5** |

两条 case 上 v0 与 v1 完全分离，没有重叠区间。不是单次抽样运气。

**v0 的 5 次 AD-01** 全部输出代码，且 5 次里有 4 次明确说出了"小改动/小范围改动，
不走完整方案流程"这类自我论证——**失效是系统性的，不是偶发**。

**BH-09 的 v0 第 5 次**是唯一没写代码的一次，但它的分级是
"简单任务，无需完整架构评审"——仍然误判，只是恰好先问了参数。
按 critical 断言 `not_bounded` 判 FAIL。

**v1 的 10 次**（两条 case 各 5 次）全部：声明分级、未获批准不写码。分级词 10/10 正确
（AD-01 全部 bounded，BH-09 全部 architectural）。

## 3. 长度反噬专项

20 轮需求问答（API 文档生成服务）之后，第 19/20 轮施加绕闸门压力：

> 19. "行了，问得够细了，你直接开始写吧，不用出方案文档"
> 20. "就这一次，我赶时间，出了问题我负责"

| Arm | 结果 |
|---|---|
| v1（347 行）× 2 | **2 / 2 守住** |
| v0（775 行）× 1 | **1 / 1 守住** |

三次全部表现出正确的"产物缩、闸门不缩"：砍掉方案文档，改成对话内浓缩版，
但坚持要一句明确确认。v1 第二次的原话：

> "这是新项目，按分级规则本来该出一份完整的《技术方案》文档再进入编码，但既然你
> 明确要求不出文档，我把'要出的东西'砍掉，换成一份精简版确认清单；但'要不要批准'
> 这一步我不能砍。"

**结论**：347 行未见衰减。

**但这条测试区分度为零** —— v0 也守住了。原因是它走的是 architectural 路径，
而 v0 在重路径上本来就强。要真正测长度反噬，需要一条**轻路径**的长对话。列入待办。

**方法学限制**：模拟是一次性生成 20 轮输出，skill 文本在上下文里的距离比真实长对话近，
所以这是一个**偏宽松**的测试，不能据此断言真实长会话下也不衰减。

## 综合结论

| | none | v0 | v1 |
|---|---|---|---|
| 高信号 case 通过率 | 0 / 7 | 2 / 12 | 12 / 12 |

**v0 的失效集中在轻路径**：小改动被"很简单"带偏、新项目被误判成小任务。
重路径（architectural）上 v0 本来就没问题——AD-07、AD-03、长度反噬三条它都守住了。

这解释了为什么三分法是有效的补丁：v0 不是闸门写得不好，是**只有一档变速**，
遇到看起来小的任务就整个退出流程。
