# after_ard — 需求覆盖检查

**档位**：全部软警告（发现问题列出来，用户回复「继续」可进入 Design）

先查项目覆盖版本 `docs/hooks/after_ard.md`，存在则用它。

## 检查

读刚落盘的 ARD，逐项检查：

**功能清单**

- 每个功能点有优先级（P0/P1/P2）并区分了 MVP 范围；
- 每个功能点有可验证的验收标准——"正常显示""功能正常"不算。

**Go 后端边界**

| 项 | 要回答的问题 |
|---|---|
| 异常路径 | 下游失败/超时/返回脏数据时怎么处理 |
| 空值与边界值 | 空列表、0、负数、超长、非法格式 |
| 状态枚举 | 涉及状态流转的，所有状态和合法转换都列了吗 |
| 并发 | 同一资源被并发修改时谁赢、怎么防重 |
| 幂等 | 写接口、扣款/发奖类是否声明幂等要求和幂等键 |
| 容量与 SLA | QPS、P99、数据量级 |
| 数据变更 | 表/字段/索引/缓存 key/MQ topic 的变更范围 |
| 依赖方 | 每个下游有没有降级说明、联调排期 |

**影响域**：「影响域分析」四个子表（新增代码 / 改动代码 / 传播链 / 高风险节点）都有内容，或明确写了「不涉及」。

**与 PRD 对照**：PRD 中的核心动作在 ARD 里都有对应功能点（漏项）；ARD 里没有 PRD 依据的功能点（越界项）单独列出。

## 输出

```
✅ ARD 覆盖检查（backend-go）
- 功能清单: N 项，验收标准完整 M/N
- 边界: 异常 ✓ 空值 ✓ 状态 ✓ 并发 ✗ 幂等 ✓ 容量 ✗ 数据 ✓ 依赖 ✓
- 影响域: 完整 / 缺 <子表>
- PRD 对照: 漏项 [...] / 越界项 [...]
```

